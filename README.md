# Booking API

REST API бронирования столиков: FastAPI, Pydantic v2, SQLAlchemy, SQLite

## Запуск

```bash
python -m venv .venv
venv/Scripts/activate
pip install -r requirements.txt
uvicorn app.main:app --reload
```

Файл БД `bookings.db` создаётся при старте - .env изменять не нужно

## Тесты

```bash
python -m pytest
```

## Принятые решения

Backend разделен на слои API, сервис, репозиторий, БД, зависимости передаются через DI FastAPI, поэтому слои легко тестировать и заменять. Уникальность активной брони на слот гарантируется частичным уникальным индексом SQLite (`WHERE status = 'active'`), а не проверкой «прочитал — записал»: это защищает от гонок при параллельных запросах, а `IntegrityError` в репозитории превращается в доменное `SlotAlreadyBookedError` (409). Отмена — это смена статуса без удаления записи, и повторная отмена дает тот же результат. Вся валидация формата, диапазонов и времени (включая запрет брони на уже прошедшее время сегодняшнего дня) работает на уровне Pydantic, поэтому невалидные данные получают стандартный 422 и не доходят до логики. Числовые границы вынесены в `core/constants.py`, чтобы правила не дублировались и менялись в одном месте.

## Что доделал бы при наличии времени

- Alembic-миграции вместо `create_all`
- Миграцию на PostgreSQL (частичные индексы поддерживаются) и async-стек SQLAlchemy
- Интегрировал деплой через контейнеризацию Docker
- Учёт часового пояса заведения при проверке «не в прошлом» (сейчас используется локальное время сервера)
- Пагинацию и дополнительные фильтры списка (по статусу, диапазону дат)
- Количество столов/вместимость вместо одной брони на слот, логирование
